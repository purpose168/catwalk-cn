# Catwalk CN 常见问题解决方案

## 概述

本文档整理了 Catwalk CN 在开发、测试、部署过程中常见问题的诊断方法和解决策略。

## 开发问题

### 1. Go 版本不兼容

**症状**:
```
go.mod:2: go 1.25.5 is not supported
```

**原因**: 使用的 Go 版本低于项目要求的版本。

**解决方案**:
```bash
# 检查当前 Go 版本
go version

# 安装或升级 Go 到 1.25.5+
# 访问 https://golang.org/dl/ 下载最新版本

# 验证版本
go version
```

**预防**: 定期更新 Go 版本，使用最新稳定版。

### 2. 依赖下载失败

**症状**:
```
go: github.com/purpose168/charm-experimental-packages-cn@v0.0.0: reading
https://proxy.golang.org/github.com/purpose168/charm-experimental-packages-
cn/@v/v0.0.0.mod: 410 Gone
```

**原因**: 依赖包不存在或已被删除。

**解决方案**:
```bash
# 清理模块缓存
go clean -modcache

# 重新下载依赖
go mod download

# 如果仍然失败，检查 go.mod 中的依赖版本
cat go.mod

# 更新依赖
go get -u ./...
```

**预防**: 定期更新依赖，使用稳定版本。

### 3. 编译错误

**症状**:
```
# github.com/purpose168/catwalk-cn
./main.go:10:2: undefined: providers
```

**原因**: 导入路径错误或包未正确导入。

**解决方案**:
```bash
# 检查导入路径
cat main.go

# 确保导入路径正确
import "github.com/purpose168/catwalk-cn/internal/providers"

# 重新构建
go build -v .
```

**预防**: 使用 IDE 的自动导入功能，避免手动输入错误。

### 4. 格式化问题

**症状**:
```
go fmt: file.go:1:1: expected 'package', found 'EOF'
```

**原因**: 文件格式不正确。

**解决方案**:
```bash
# 格式化代码
go fmt ./...

# 使用 golangci-lint 检查
golangci-lint run ./...

# 修复问题
golangci-lint run --fix ./...
```

**预防**: 在提交前运行格式化和检查。

## 运行时问题

### 1. 端口被占用

**症状**:
```
listen tcp :8080: bind: address already in use
```

**原因**: 端口 8080 已被其他进程占用。

**解决方案**:
```bash
# 查找占用端口的进程
sudo netstat -tlnp | grep 8080
# 或
sudo lsof -i :8080

# 杀死占用端口的进程
sudo kill -9 <PID>

# 或使用其他端口
# 修改 main.go 中的端口号
server := &http.Server{
    Addr: ":8081",
    // ...
}
```

**预防**: 使用环境变量配置端口，避免硬编码。

## API 问题

### 1. 404 Not Found

**症状**:
```
curl http://localhost:8080/invalid
404 page not found
```

**原因**: 请求的端点不存在。

**解决方案**:
```bash
# 检查可用的端点
curl http://localhost:8080/healthz

# 检查路由配置
cat main.go

# 使用正确的端点
curl http://localhost:8080/v2/providers
```

**预防**: 查看 API 文档，使用正确的端点。

### 2. 405 Method Not Allowed

**症状**:
```
curl -X POST http://localhost:8080/v2/providers
Method not allowed
```

**原因**: 使用了不支持的 HTTP 方法。

**解决方案**:
```bash
# 使用正确的 HTTP 方法
curl -X GET http://localhost:8080/v2/providers

# 或使用 curl 默认的 GET 方法
curl http://localhost:8080/v2/providers
```

**预防**: 查看 API 文档，使用正确的 HTTP 方法。

### 3. ETag 缓存问题

**症状**:
```
curl -H "If-None-Match: \"invalid\"" http://localhost:8080/v2/providers
# 返回完整数据而不是 304
```

**原因**: ETag 值不正确。

**解决方案**:
```bash
# 首次请求获取 ETag
curl -I http://localhost:8080/v2/providers

# 使用正确的 ETag
curl -H "If-None-Match: \"33a64df551425fcc55e4d42a148795d9f25f89d4\""
http://localhost:8080/v2/providers
```

**预防**: 使用 HEAD 请求获取 ETag，确保使用正确的值。

### 1. 测试失败

**症状**:

```bash
# 确保端点正确

```

**预防**: 编写测试前先验证端点存在。

### 2. 测试覆盖率低

**症状**:
```
coverage: 45.2% of statements
```

**原因**: 测试不充分。

**解决方案**:
```bash

go test -cover ./...
```

### 3. 竞态条件

**症状**:
```
WARNING: DATA RACE
Read at 0x00c0000b6008 by goroutine 8:
  main.providersHandler()
```

**原因**: 并发访问共享数据。

**解决方案**:
```bash
# 运行竞态检测
go test -race ./...

# 修复竞态条件
# 使用 sync.Mutex 或 channel 保护共享数据

# 重新运行测试
go test -race ./...
```

**预防**: 使用竞态检测工具，避免共享状态。

## 部署问题

### 1. 服务无法启动

**症状**:
```
sudo systemctl start catwalk-cn
Job for catwalk-cn.service failed
```

**原因**: 配置错误或权限问题。

**解决方案**:
```bash
# 查看服务状态
sudo systemctl status catwalk-cn

# 查看日志
sudo journalctl -u catwalk-cn -n 50

# 检查配置文件
sudo cat /etc/systemd/system/catwalk-cn.service

# 修复配置
# 重新加载配置
sudo systemctl daemon-reload

# 启动服务
sudo systemctl start catwalk-cn
```

**预防**: 在部署前测试服务配置。

### 2. Docker 容器无法启动

**症状**:
```
docker run -p 8080:8080 catwalk-cn:latest
Error: ...
```

**原因**: Dockerfile 错误或依赖问题。

**解决方案**:
```bash
# 查看容器日志
docker logs <container-id>

# 检查 Dockerfile
cat Dockerfile

# 重新构建镜像
docker build -t catwalk-cn:latest .

# 运行容器
docker run -p 8080:8080 catwalk-cn:latest
```

**预防**: 在本地测试 Dockerfile，确保镜像可以正常构建和运行。

### 3. Kubernetes Pod 无法启动

**症状**:
```
kubectl get pods
NAME          READY   STATUS             RESTARTS   AGE
catwalk-cn    0/1     CrashLoopBackOff   5          5m
```

**原因**: 配置错误或资源不足。

**解决方案**:
```bash
# 查看 Pod 状态
kubectl describe pod catwalk-cn

# 查看 Pod 日志
kubectl logs catwalk-cn

# 检查配置
kubectl get deployment catwalk-cn -o yaml

# 修复配置
kubectl apply -f deployment.yaml

# 删除并重新创建 Pod
kubectl delete pod catwalk-cn
```

**预防**: 在部署前测试 Kubernetes 配置。

```bash
# 优化热点函数

# 使用缓存
```

**预防**: 定期进行性能分析，优化热点代码。

### 2. 内存泄漏

**症状**:
```
# 内存使用持续增长
top
PID   USER      PR  NI    VIRT    RES    SHR S  %CPU  %MEM
12345 catwalk   20   0   1.2g    800m   100m R  10.0  20.0
```

**原因**: 未释放内存或 goroutine 泄漏。

**解决方案**:
```bash
# 使用 pprof 分析内存
go tool pprof http://localhost:8080/debug/pprof/heap

# 查看内存分配
go tool pprof -http=:8080 http://localhost:8080/debug/pprof/heap

# 修复内存泄漏
# 释放不再使用的资源
# 关闭 goroutine
```

**预防**: 使用 pprof 定期检查内存使用，及时修复泄漏。

### 3. CPU 使用率过高

**症状**:

**原因**: 无限循环或计算密集型操作。

**解决方案**:

```bash
# 查看热点函数
go tool pprof -http=:8080 http://localhost:8080/debug/pprof/profile

# 优化热点函数
# 减少计算量
# 使用缓存
```

**预防**: 定期进行性能分析，优化热点代码。

## 依赖问题

### 1. 依赖冲突

**症状**:
```
go: github.com/purpose168/charm-experimental-packages-cn@v0.0.0 requires
github.com/charmbracelet/x/etag@v0.2.0: conflicting requirements
```

**原因**: 不同包要求不同版本的依赖。

**解决方案**:
```bash
# 更新依赖
go get -u ./...

# 或手动指定版本
go get github.com/charmbracelet/x/etag@v0.2.0

# 整理依赖
go mod tidy
```

**预防**: 定期更新依赖，保持依赖版本一致。

### 2. 依赖安全漏洞

**症状**:
```
go: github.com/purpose168/charm-experimental-packages-cn@v0.0.0 has security
vulnerabilities
```

**原因**: 依赖包存在安全漏洞。

**解决方案**:
```bash
# 检查安全漏洞
go list -json -m all | nancy sleuth

# 更新依赖
go get -u ./...

# 或手动更新有漏洞的包
go get -u github.com/vulnerable/package

# 整理依赖
go mod tidy
```

**预防**: 定期检查安全漏洞，及时更新依赖。

2. **运行时问题**: 端口占用、配置加载、内存不足
3. **API 问题**: 404、405、ETag 缓存
4. **测试问题**: 测试失败、覆盖率低、竞态条件
5. **部署问题**: 服务启动、Docker、Kubernetes
6. **性能问题**: 响应时间、内存泄漏、CPU 使用
7. **监控问题**: Prometheus、Grafana
8. **依赖问题**: 依赖冲突、安全漏洞
