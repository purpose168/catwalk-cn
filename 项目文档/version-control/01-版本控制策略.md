# Catwalk CN 版本控制策略

## 概述

本文档制定了 Catwalk CN 项目的版本控制策略，包括分支管理策略、代码合并流程及版本号命名规则。

## 版本控制工具

### Git

Catwalk CN 使用 Git 作为版本控制系统。

### 远程仓库

- **GitHub**: https://github.com/purpose168/catwalk-cn

## 分支管理策略

### 分支类型

#### 主分支

| 分支 | 说明 | 保护状态 |
|------|------|---------|
| `main` | 主分支，用于生产环境 | ✅ 受保护 |
| `develop` | 开发分支，用于集成开发 | ✅ 受保护 |

#### 功能分支

| 分支模式 | 说明 | 命名规则 |
|---------|------|---------|
| 功能分支 | 开发新功能 | `feature/<feature-name>` |
| 修复分支 | 修复 bug | `fix/<bug-description>` |
| 发布分支 | 准备发布 | `release/<version>` |
| 热修复分支 | 紧急修复生产问题 | `hotfix/<version>` |

### 分支命名规则

#### 功能分支

```
feature/add-deepseek-provider
feature/etag-caching
feature/prometheus-metrics
```

#### 修复分支

```
fix/etag-mismatch
fix/health-check-timeout
fix/provider-loading-error
```

#### 发布分支

```
release/v0.1.0
release/v0.2.0
```

#### 热修复分支

```
hotfix/v0.1.1
hotfix/v0.2.1
```

## 分支工作流

### Git Flow 工作流

```
                    main
                     │
                     │
                     ▼
              release/v0.1.0
                     │
                     │
                     ▼
                    develop
                     │
        ┌────────────┼────────────┐
        │            │            │
        ▼            ▼            ▼
feature/A    feature/B    feature/C
```

### 功能开发流程

#### 1. 创建功能分支

```bash
git checkout develop
git pull origin develop
git checkout -b feature/add-deepseek-provider
```

#### 2. 开发功能

```bash
# 编写代码
git add .
git commit -m "feat(providers): 添加 DeepSeek 提供商支持"
```

#### 3. 推送分支

```bash
git push origin feature/add-deepseek-provider
```

#### 4. 创建 Pull Request

在 GitHub 上创建 Pull Request：
- 源分支: `feature/add-deepseek-provider`
- 目标分支: `develop`
- 描述: 详细说明功能变更

#### 5. 代码审查

- 至少一名团队成员审查
- 解决所有审查意见
- 通过 CI 检查

#### 6. 合并分支

```bash
# 合并到 develop
git checkout develop
git pull origin develop
git merge --no-ff feature/add-deepseek-provider
git push origin develop

# 删除功能分支
git branch -d feature/add-deepseek-provider
git push origin --delete feature/add-deepseek-provider
```

### 修复流程

#### 1. 创建修复分支

```bash
git checkout develop
git pull origin develop
git checkout -b fix/etag-mismatch
```

#### 2. 修复问题

```bash
# 修复代码
git add .
git commit -m "fix(api): 修复 ETag 不匹配问题"
```

#### 3. 推送和合并

```bash
git push origin fix/etag-mismatch
# 创建 Pull Request
# 代码审查
# 合并到 develop
```

### 发布流程

#### 1. 创建发布分支

```bash
git checkout develop
git pull origin develop
git checkout -b release/v0.1.0
```

#### 2. 准备发布

```bash
# 更新版本号
# 更新 CHANGELOG
git add .
git commit -m "chore(release): 准备 v0.1.0 发布"
```

#### 3. 测试发布

```bash
# 运行测试
go test ./...
```

#### 4. 合并到 main

```bash
git checkout main
git merge --no-ff release/v0.1.0
git tag -a v0.1.0 -m "Release v0.1.0"
git push origin main
git push origin v0.1.0
```

#### 5. 合并回 develop

```bash
git checkout develop
git merge --no-ff release/v0.1.0
git push origin develop
```

#### 6. 删除发布分支

```bash
git branch -d release/v0.1.0
git push origin --delete release/v0.1.0
```

### 热修复流程

#### 1. 创建热修复分支

```bash
git checkout main
git pull origin main
git checkout -b hotfix/v0.1.1
```

#### 2. 修复问题

```bash
# 修复代码
git add .

```

#### 3. 测试修复

```bash

```

#### 4. 合并到 main


#### 5. 合并回 develop

```bash
git checkout develop
```

#### 6. 删除热修复分支

```bash
git branch -d hotfix/v0.1.1
git push origin --delete hotfix/v0.1.1
```

## 版本号命名规则

### 语义化版本（SemVer）

Catwalk CN 遵循语义化版本规范（[SemVer](https://semver.org/)）。

### 版本格式

```
MAJOR.MINOR.PATCH
```

### 版本号规则

| 版本号 | 说明 | 示例 |
|--------|------|------|
| **MAJOR** | 不兼容的 API 变更 | `1.0.0` → `2.0.0` |
| **MINOR** | 向后兼容的功能新增 | `1.0.0` → `1.1.0` |
| **PATCH** | 向后兼容的问题修复 | `1.0.0` → `1.0.1` |

### 预发布版本

```
MAJOR.MINOR.PATCH-PRERELEASE
```

示例：
- `v1.0.0-alpha.1`
- `v1.0.0-beta.1`
- `v1.0.0-rc.1`

### 构建元数据

```
MAJOR.MINOR.PATCH+BUILD
```

示例：
- `v1.0.0+20240101`
- `v1.0.0+abc123`

## 提交信息规范

### 约定式提交（Conventional Commits）

```
<type>(<scope>): <subject>

<body>

<footer>
```

### 类型（type）

| 类型 | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | 修复 bug |
| `docs` | 文档更新 |
| `style` | 代码格式调整 |
| `refactor` | 重构 |
| `test` | 测试相关 |
| `chore` | 构建/工具相关 |
| `perf` | 性能优化 |
| `ci` | CI 配置 |

### 作用域（scope）

| 作用域 | 说明 |
|--------|------|
| `providers` | 提供商相关 |
| `api` | API 相关 |
| `docs` | 文档相关 |
| `build` | 构建相关 |
| `deps` | 依赖相关 |

### 示例

#### 新功能

```
feat(providers): 添加 DeepSeek 提供商支持

添加了 DeepSeek 提供商的配置文件和注册函数。
包含 DeepSeek-V3 和 DeepSeek-Coder 模型。

Closes #123
```

#### 修复 bug

```
fix(api): 修复 ETag 缓存问题

修复了 ETag 不匹配时的响应问题，
现在正确返回 304 Not Modified。

Fixes #456
```

#### 文档更新

```
docs(readme): 更新安装说明

更新了 README 中的安装步骤，
添加了 Docker 部署说明。
```

#### 重构

```
refactor(providers): 优化提供商加载逻辑

使用 Go embed 替代文件读取，
简化了部署流程。
```

## 代码合并流程

### Pull Request 流程

#### 1. 创建 Pull Request

在 GitHub 上创建 Pull Request：
- 填写标题和描述
- 关联相关 Issue
- 选择审查者

#### 2. 代码审查

- 审查者检查代码
- 提出修改意见
- 开发者修改代码

#### 3. CI 检查

- 自动运行测试
- 检查代码覆盖率
- 运行代码检查

#### 4. 合并

- 所有审查通过
- CI 检查通过
- 使用 Squash and Merge 合并

### 合并策略

| 策略 | 说明 | 使用场景 |
|------|------|---------|
| **Squash and Merge** | 压缩提交为单个提交 | 功能分支 |
| **Merge Commit** | 保留完整历史 | 发布分支 |
| **Rebase and Merge** | 变基后合并 | 不推荐 |

## 分支保护规则

### main 分支

- ✅ 需要 Pull Request
- ✅ 需要至少 1 个审查
- ✅ 需要通过 CI 检查
- ✅ 需要更新到最新
- ✅ 限制推送权限

### develop 分支

- ✅ 需要 Pull Request
- ✅ 需要至少 1 个审查
- ✅ 需要通过 CI 检查
- ✅ 需要更新到最新
- ✅ 限制推送权限

## 标签管理

### 标签命名

```
v<MAJOR>.<MINOR>.<PATCH>
```

示例：
- `v0.1.0`
- `v0.2.0`
- `v1.0.0`

### 创建标签

```bash
# 创建轻量标签
git tag v0.1.0

# 创建带注释的标签
git tag -a v0.1.0 -m "Release v0.1.0"

# 推送标签
git push origin v0.1.0

# 推送所有标签
git push origin --tags
```

### 删除标签

```bash
# 删除本地标签
git tag -d v0.1.0

# 删除远程标签
git push origin --delete v0.1.0
```

## 发布流程

### 1. 准备发布

```bash
# 创建发布分支
git checkout develop
git checkout -b release/v0.1.0

# 更新版本号
# 更新 CHANGELOG
git add .
git commit -m "chore(release): 准备 v0.1.0 发布"
```

### 2. 测试发布

```bash
# 运行测试
go test ./...

# 构建项目
make compile
```

### 3. 合并到 main

```bash
git checkout main
git merge --no-ff release/v0.1.0
git tag -a v0.1.0 -m "Release v0.1.0"
git push origin main
git push origin v0.1.0
```

### 4. 合并回 develop

```bash
git checkout develop
git merge --no-ff release/v0.1.0
git push origin develop
```

### 5. 创建 GitHub Release

在 GitHub 上创建 Release：
- 选择标签
- 填写标题和描述
- 上传二进制文件

## 版本回退

### 回退到指定版本

```bash
# 回退到指定标签
git checkout v0.1.0

# 创建新分支
git checkout -b hotfix/v0.1.1
```

### 回退提交

```bash
# 回退单个提交
git revert <commit-hash>

# 回退多个提交
git revert <commit-hash1> <commit-hash2>
```

## 总结

遵循这些版本控制策略可以确保：

1. **清晰的分支管理**: 明确的分支类型和工作流
2. **规范的版本号**: 遵循语义化版本规范
3. **规范的提交信息**: 使用约定式提交
4. **安全的合并流程**: 通过审查和 CI 检查
5. **可靠的发布流程**: 标准化的发布流程

所有开发者都应遵循这些版本控制策略，以维护 Catwalk CN 的稳定性和可维护性。
