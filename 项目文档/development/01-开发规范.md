# Catwalk CN 开发规范

## 概述

本文档制定了 Catwalk CN 项目的开发规范，包括编码规范、命名规范、代码审查标准及文档编写规范，确保代码质量和团队协作效率。

## 编码规范

### Go 代码规范

Catwalk CN 遵循 Go 语言官方代码规范和 [Effective Go](https://golang.org/doc/effective_go)。

#### 格式化

使用 `gofmt` 格式化代码：

```bash
go fmt ./...
```

或使用 Taskfile：

```bash
task fmt
```

#### 导入顺序

导入包按以下顺序排列：

1. 标准库
2. 第三方库
3. 项目内部包

```go
import (
    "encoding/json"
    "log"
    "net/http"

    "github.com/prometheus/client_golang/prometheus"
    "github.com/prometheus/client_golang/prometheus/promauto"

    "github.com/purpose168/charm-experimental-packages-cn/etag"
    "github.com/purpose168/catwalk-cn/pkg/catwalk"
)
```

#### 错误处理

- 不要忽略错误
- 使用 `log.Fatal` 处理初始化错误
- 使用 `http.Error` 处理 HTTP 错误

```go
// 正确
if err := json.Unmarshal(configData, &p); err != nil {
    log.Fatal(err)
}

// 错误
json.Unmarshal(configData, &p)  // 忽略错误
```

#### 注释

- 导出的包必须有包注释
- 导出的函数必须有函数注释
- 复杂逻辑必须有行内注释

```go
// Package catwalk 提供 AI 推理提供商和模型的数据库。
package catwalk

// GetAll 返回所有已注册的 AI 提供商配置。
func GetAll() []Provider {
    providers := make([]Provider, 0, len(providerRegistry))
    for _, providerFunc := range providerRegistry {
        providers = append(providers, providerFunc())
    }
    return providers
}
```

#### 并发

- 使用 goroutine 处理并发请求
- 避免共享状态
- 使用 channel 进行通信

```go
// HTTP 服务器自动处理并发
server := &http.Server{
    Addr:    ":8080",
    Handler: mux,
}
```

## 命名规范

### 文件命名

- 使用小写字母
- 使用下划线分隔单词
- 文件名应简洁且描述性强

```
main.go
providers.go
provider.go
```

### 包命名

- 使用小写字母
- 单个单词
- 简洁且描述性强

```
package main
package catwalk
package providers
```

### 变量命名

#### 局部变量

使用驼峰命名法：

```go
providersJSON := []byte{}
providersETag := ""
```

#### 导出变量

使用驼峰命名法，首字母大写：

```go
var (
    providersJSON []byte
    providersETag string
)
```

#### 常量

使用驼峰命名法，首字母大写：

```go
const (
    TypeOpenAI       Type = "openai"
    TypeOpenAICompat Type = "openai-compat"
)
```

### 函数命名

#### 导出函数

使用驼峰命名法，首字母大写：

```go
func GetAll() []Provider
func loadProviderFromConfig(configData []byte) Provider
```

#### 私有函数

使用驼峰命名法，首字母小写：

```go
func loadProviderFromConfig(configData []byte) Provider
func providersHandler(w http.ResponseWriter, r *http.Request)
```

### 接口命名

- 单个方法：使用方法名 + er 后缀
- 多个方法：使用描述性名称

```go
type ProviderFunc func() Provider
type Handler interface {
    ServeHTTP(w http.ResponseWriter, r *http.Request)
}
```

### 类型命名

使用驼峰命名法，首字母大写：

```go
type Provider struct {}
type Model struct {}
type Type string
```

## 代码审查标准

### 审查清单

#### 功能性

- [ ] 代码实现了预期的功能
- [ ] 边界条件得到正确处理
- [ ] 错误处理完整且正确
- [ ] 没有明显的逻辑错误

#### 性能

- [ ] 没有明显的性能问题
- [ ] 使用了适当的数据结构
- [ ] 避免了不必要的内存分配
- [ ] 使用了缓存（如适用）

#### 安全性

- [ ] 没有安全漏洞
- [ ] 输入验证完整
- [ ] 没有敏感信息泄露
- [ ] 依赖项是最新的

#### 可维护性

- [ ] 代码结构清晰
- [ ] 命名规范一致
- [ ] 注释充分且准确
- [ ] 没有重复代码

#### 测试

- [ ] 有充分的单元测试
- [ ] 测试覆盖主要功能
- [ ] 测试通过

### 审查流程

1. 创建 Pull Request
2. 至少一名团队成员审查
3. 解决所有审查意见
4. 通过 CI 检查
5. 合并到主分支

### 审查工具

使用 `golangci-lint` 进行代码检查：

```bash
golangci-lint run ./...
```

或使用 Taskfile：

```bash
task lint
```

## 文档编写规范

### 代码注释

#### 包注释

每个包必须有包注释，描述包的用途：

```go
// Package catwalk 提供 AI 推理提供商和模型的数据库。
// 
// Catwalk CN 是一个 HTTP 服务，提供 RESTful API 接口
// 供客户端查询 AI 提供商和模型信息。
package catwalk
```

#### 函数注释

导出的函数必须有函数注释，说明函数的用途、参数和返回值：

```go
// GetAll 返回所有已注册的 AI 提供商配置。
//
// 返回值:
//   - []Provider: 提供商列表
func GetAll() []Provider {
    providers := make([]Provider, 0, len(providerRegistry))
    for _, providerFunc := range providerRegistry {
        providers = append(providers, providerFunc())
    }
    return providers
}
```

#### 类型注释

导出的类型必须有类型注释，说明类型的用途：

```go
// Provider 表示 AI 提供商的配置信息。
type Provider struct {
    Name   string            // 提供商名称
    ID     InferenceProvider // 推理提供商ID
    Models []Model           // 模型列表
}
```

- 安装说明
- 使用示例
- API 文档链接

- 许可证

API 文档应包含：

- 端点列表
- 请求方法
- 请求参数
- 响应格式
- 错误码
- 使用示例

### 代码示例

提供清晰、可运行的代码示例：

```go
package main

import (
    "encoding/json"
    "fmt"
    "net/http"
)

func main() {
    resp, err := http.Get("http://localhost:8080/v2/providers")
    if err != nil {
        panic(err)
    }
    defer resp.Body.Close()

    var providers []Provider
    if err := json.NewDecoder(resp.Body).Decode(&providers); err != nil {
        panic(err)
    }

    fmt.Printf("Found %d providers\n", len(providers))
}
```

## Git 提交规范

### 提交信息格式

使用约定式提交（Conventional Commits）：

```
<type>(<scope>): <subject>

<body>

<footer>
```

### 类型（type）

- `feat`: 新功能
- `fix`: 修复 bug
- `docs`: 文档更新
- `style`: 代码格式调整
- `refactor`: 重构
- `test`: 测试相关
- `chore`: 构建/工具相关

### 示例

```
feat(providers): 添加 DeepSeek 提供商支持

添加了 DeepSeek 提供商的配置文件和注册函数。
包含 DeepSeek-V3 和 DeepSeek-Coder 模型。

Closes #123
```

```
fix(api): 修复 ETag 缓存问题

修复了 ETag 不匹配时的响应问题，
现在正确返回 304 Not Modified。

Fixes #456
```

## 测试规范

### 单元测试

- 每个包都应有单元测试
- 测试文件命名为 `*_test.go`
- 使用表驱动测试

```go
func TestGetAll(t *testing.T) {
    tests := []struct {
        name     string
        expected int
    }{
        {"should return providers", 21},
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            providers := GetAll()
            if len(providers) != tt.expected {
                t.Errorf("expected %d providers, got %d", tt.expected, len(providers))
            }
        })
    }
}
```

### 集成测试

- 测试 HTTP 端点
- 测试缓存行为
- 测试错误处理

```go
func TestProvidersHandler(t *testing.T) {
    req := httptest.NewRequest("GET", "/v2/providers", nil)
    w := httptest.NewRecorder()

    providersHandler(w, req)

    if w.Code != http.StatusOK {
        t.Errorf("expected status 200, got %d", w.Code)
    }

    if w.Header().Get("Content-Type") != "application/json" {
        t.Error("expected Content-Type application/json")
    }
}
```

## 性能规范

### 响应时间

- API 响应时间应 < 100ms
- 健康检查响应时间应 < 10ms

### 内存使用

- 内存使用应保持稳定
- 避免内存泄漏

### 并发

- 支持高并发请求
- 使用 goroutine 处理并发

## 安全规范

### 输入验证

- 验证所有输入
- 防止注入攻击

### 敏感信息

- 不在代码中硬编码密钥
- 使用环境变量
- 不在日志中记录敏感信息

### 依赖管理

- 定期更新依赖
- 使用 `go mod tidy` 清理依赖
- 检查依赖漏洞

## 版本管理

### 语义化版本

遵循语义化版本（SemVer）：

- `MAJOR.MINOR.PATCH`
- MAJOR: 不兼容的 API 变更
- MINOR: 向后兼容的功能新增
- PATCH: 向后兼容的问题修复

### 发布流程

1. 更新版本号
2. 更新 CHANGELOG
3. 创建 Git 标签
4. 推送标签
5. 发布 Release

## 总结

遵循这些开发规范可以确保：

1. **代码质量**: 一致、清晰、可维护
2. **团队协作**: 高效、顺畅、无冲突
3. **项目稳定**: 可靠、安全、高性能
4. **文档完善**: 清晰、准确、有用

所有开发者都应熟悉并遵循这些规范，以维护 Catwalk CN 的高质量标准。
